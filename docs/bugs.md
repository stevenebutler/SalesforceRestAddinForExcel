Known Bugs and Issues

1. ~~Table Query Wizard screen 1 is not useful. The second screen should be screen 1 and can display the selected destination cell at the top.~~ **Fixed:** Excel InputBox still picks the anchor; WPF opens on object selection with **Destination cell: {A1}** on every step (no useless confirm screen).
2. ~~When downloading I don't see any progress being registered. SF provides a totalCount when running the query I think, so it should be possible to keep the download status with a realistic looking progress bar (WPF progress bar, with record count, records downloaded if possible).~~ **Fixed** (with #3/#4): Query Table reports downloaded/`totalSize` per page; determinate WPF progress bar.
3. ~~One of the progress dialogs clips the button at the bottom (while also not showing any visible progress meter/info).~~ **Fixed:** `DataOperationProgressWindow` uses `SizeToContent.Height`; progress host pumps the WPF dispatcher while waiting; Query Table reports downloaded/`totalSize` per page.
4. ~~Progress bars should permit downloads to be cancelled. Cancelling before the download is complete (for all pages) will prevent any clearing of the screen.~~ **Fixed:** progress host uses modal `ShowDialog` (nested WPF message loop) so Cancel is processed; cancelled queries skip sheet clear/write.
5. ~~When updating the range with downloaded data, the old range is not cleared. This is a problem when the old range is much larger than the new range (e.g. filter criteria is changed). There should be a range clear for the table cells within the entity being updated (not for other entities that may be on the same page, so the clear should focus on clearing the range, not deleting rows etc.) Clearing should clear all, not just values in the range.~~ **Fixed:** `ClearBody.EndRow` covers `max(existing body, new projection)` within the table column span; Excel `Range.Clear()` (values + formats + comments).
6. ~~**Excel process stays alive after close (zombie `EXCEL.EXE`).**~~ **Fixed:** Excel COM from thread-pool continuations after `await` (e.g. `excel.StatusBar` in progress reports) pinned the process. `ExcelComThread` marshals COM onto the Excel STA; plus WPF `Shutdown` on `OnBeginShutdown` / RCW GC. Verified: Excel exits cleanly after Query Table Data.
7. ~~**Initial login / refresh-token restore has no progress feedback.**~~ **Fixed:** `EnsureLoggedInAndRefreshUi` (and all other STA waits) go through `ExcelStaAsyncHost` — modal WPF progress/status UI + StatusBar. `Dispatcher.PushFrame` / split `ExcelMacroAsync` + `ExcelStatusBar` + `DataOperationProgressHost` removed (NFR-STA-1).
8. ~~**Wizard field list needs richer labels + clearer custom-after-standard ordering.**~~ **Fixed:** field picker shows `{Label} ({ApiName})` with type tooltip and eight-bucket pastel row fills + legend; `OrderFieldsForWizard` is Id → Name → Required (std/custom) → Standard → Custom → Read-only (std/custom), then describe order within a bucket (FR-TQW-6 / T-WIZ-01).
9. **Legacy wizard operator set does not match the current `in` / `on` assumptions.** See [legacy-criteria-compatibility.md](legacy-criteria-compatibility.md) for the operator matrix and value-formatting details. The actual legacy Table Query Wizard operator dropdown offered `equals`, `not equals`, `like`, `starts with`, `ends with`, `less than`, `greater than`, `includes`, `excludes`, and `regexp`. It did **not** expose `in` / `on` as visible user options, even though the parser can still understand some `in` / `on` cases for compatibility when a workbook already contains them. The solution should bias toward legacy-app compatibility and preserve the legacy wizard's visible operator semantics rather than inventing new choices. Do not implement until the compatibility story is clear.
10. ~~**Table Query Wizard should clear a separator column to the right of the new table.**~~ **Fixed:** `WizardTableLayoutWriter` clears the column immediately right of the last field for object + header rows (`Range.Clear`) so multi-table discovery keeps a blank gap (FR-QTD-1).
11. ~~**Ribbon display name / group label.**~~ **Fixed:** tab label `Salesforce Rest`; group label `Instance: {host|(none)}  User: {name|(not signed in)|(unknown)}`.
12. ~~**`TreatWarningsAsErrors` is still off.**~~ **Fixed:** nullable/CS warnings cleared across Core, Windows.Ui, and ExcelDna; `Directory.Build.props` now has `<TreatWarningsAsErrors>true</TreatWarningsAsErrors>`.
13. **`Use Reference Name/Id` appears to have no effect.** Options persists `UseReference`, and specs say lookup/reference cells should resolve Name↔Id on query/update/insert/criteria. Investigation: Core has `IReferenceResolver` + unit-test fake only — **no production Salesforce resolver**. Excel host never passes `ReferenceResolver` into `QueryTableInput` / `UpdateCellsInput` / insert. `FieldValueConverter.ToSalesforceValue` does not call Name→Id (stringifies the cell); display path only substitutes a pre-resolved name when one is already supplied. So toggling the checkbox cannot change runtime behaviour today. Do not implement until product confirms expected UX (which fields, Name vs Id display on query, failure when name not found, etc.).
14. ~~**Table Query Wizard entity selection page only uses a simple list box and lacks Standard / Custom / System filters.**~~ **Fixed:** the first wizard page now shows a two-column `Label` / `API Name` table with `Standard Objects`, `Custom Objects`, and `System Objects` filters; `System Objects` is unchecked by default and the object list follows the legacy standard-object allowlist plus the `custom` flag for custom objects.
15. **Going Back in the Table Query Wizard from the clause selection screen throws `InvalidOperationException`.** User-visible impact: clicking Back from the clause selection screen causes Table Query Wizard to fail with `Specified element is already the logical child of another element. Disconnect it first.` Type: `System.InvalidOperationException`.
16. **Add logging for header-row read timing.** User-visible impact: when capturing a table, log how long it takes to read the header row, split into the range-value read and the individual note/comment reads, so we can see whether comments are the slow part. Do not change behavior, only add instrumentation.
17. **Query completion status should include elapsed time.** User-visible impact: when a query operation finishes, the status message written to the status bar should include the total query time, including `queryMore` pagination, and also the time spent updating the worksheet. Do not change the operation flow, only enrich the completion message.
18. ~~**Table Query Wizard writes literal `and` into criteria cells.**~~ **Fixed:** criteria rows now write contiguous `[field] [operator] [value]` triplets with no separator token, so the query runner no longer sees a fake `and` field.
19. ~~Table Query Wizard crashes when filtering a single-select object picker with an existing selection.~~ **Fixed:** `ObjectPickerControl` suppresses selection events during filter refresh and restores single-select state via `SelectedItem`, so changing the filter no longer throws in the wizard.
